# 雪季出行工作台

把手里的滑雪、酒店套餐整理到一起，按出行日期、人数和预算比较搭配，保存适合自己的出行方案。作为 DSH Web 插件使用，可通过对话录入资料，也可在工作台查看和管理。

## 能做什么

- **录入套餐**：粘贴套餐说明或上传截图，整理酒店、房型、住宿晚数、有效期、补款规则，以及雪票、早餐、汤泉等权益。
- **持续补全资料**：已购买、未购买和资料不完整的套餐都可以记录；不清楚的信息保留为待确认，之后继续补充。保存或修改前会展示确认卡片。
- **查找出行候选**：按日期、住宿晚数、目的地、标签或关键词筛选套餐，查看购买状态、剩余间夜和资料完整度。
- **规划与比较**：确认出行条件和共同费用后，从资料完整的套餐中生成候选，比较住宿搭配、补款、权益覆盖和整趟成本，支持多段住宿。
- **保存与继续调整**：选择并保存方案，随时查看行程与费用明细，回到会话继续讨论或生成调整后的方案。
- **管理关联资料**：在会话旁查看套餐和方案，将资料添加到下一条消息中；支持搜索会话、重命名及删除不再需要的套餐或方案。

## 安装前准备

- 已安装并能正常使用 DSH Web，且已配置可用模型。本插件当前适配 DSH `0.1.7-rc.2`。
- 已安装 Node.js `22.19` 或更高版本、Git 和 pnpm。
- 源码开发使用 pnpm `11.7.0`，与仓库的 `packageManager` 和 CI 保持一致。
- 使用截图录入时，需要所选模型支持图片识别。

## 从源码安装

在仓库根目录安装依赖；安装会自动构建所有工作台：

```sh
git clone https://github.com/familyDppXpp/dsh-snow-trip.git
cd dsh-snow-trip
pnpm install
```

安装已构建的雪季包到 DSH，然后启动：

```sh
dsh plugin --profile web add "$PWD/packages/snow-trip"
dsh web
```

如果使用源码版 DSH，在 **DSH 源码根目录**执行，将路径替换为本仓库中的插件目录：

```sh
pnpm dsh plugin --profile web add /绝对路径/dsh-snow-trip/packages/snow-trip
pnpm dsh web
```

仓库根目录是开发工作区，不是插件包；不再使用旧的仓库根目录 Git 安装命令。

## 打包分发

在仓库根目录执行，打包前会自动构建雪季包：

```sh
pnpm --filter dsh-snow-trip pack
```

将输出的 `.tgz` 文件交给使用者，安装时无需构建源码：

```sh
dsh plugin --profile web add /绝对路径/dsh-snow-trip-0.1.0.tgz
dsh web
```

## 打开工作台

打开启动命令输出的浏览器地址，点击 DSH 侧栏中的「雪季出行」。如果安装前 DSH 已在运行，请重启后刷新页面。

也可以在启动时给出的登录地址末尾加上 `#app=snow-trip`，直接进入工作台。例如：

```text
http://127.0.0.1:端口/?token=启动时给出的token#app=snow-trip
```

以后启动只需运行 `dsh web`；源码版 DSH 在其源码根目录运行 `pnpm dsh web`。在运行服务的终端按 `Ctrl+C` 可停止。

## 开始使用

### 1. 录入手里的套餐

点击「出发去山野」，选择「录入套餐」，粘贴说明或上传截图，并补充你已知的信息。例如：

> 帮我录入这份长白山住宿套餐，2 晚，报价 1299 元，还没有购买。酒店和有效期暂时不清楚。

助理会整理资料，必要时向你提问。检查确认卡中的金额、日期和权益，点击「确认保存」完成录入；有误则选择「继续调整」。不确定的信息可以先保留，之后从「已录套餐」中继续补全。

### 2. 规划一次出行

选择「规划出行」，说明日期、住宿晚数、人数和偏好。例如：

> 我们 2 人计划 12 月 31 日入住，住 4 晚，滑雪 3 天，总预算 6000 元。看看已有套餐怎么搭配合适。

先回答必要的问题，再核对出行条件、参与搭配的套餐和共同费用，点击「生成方案」。可以指定套餐范围；未指定时，会从全部资料完整的套餐中筛选。

### 3. 比较并保存方案

查看候选方案的住宿安排、费用明细与推荐理由，可以继续提问或补充要求。勾选想保留的方案并点击「保存所选」，之后在「已存方案」中查看。

需要改变日期、人数或费用时，选择「继续规划」讨论调整。说“更新套餐信息”即可自动核对最新套餐；保存前查看修改前后差异，默认更新原方案，也可另存为新方案。仅统一套餐、目的地或雪场名称时保留预约与退改信息；实际行程变化会提示重置。操作完成后，卡片保留只读差异、用户操作及保存结果。

## 使用提示

- 套餐筛选和方案核算基于你录入的资料，不代表酒店实时房态或已经完成预订。
- 未知费用不会自动当作零；模型估算的费用需要你核对确认。
- 删除套餐时，引用它的已存方案也会受到影响，确认前请查看页面列出的范围。
- 会话、附件与套餐资料保存在本机；处理任务时，相关文字和图片会发送给你在 DSH 中选择的模型。

已存方案支持在会话中说“把这个方案改名为……”，核对原标题与新标题后确认保存。改名不重新核算、不刷新套餐快照；后续更新原方案仍保留该标题。

## 开发目录与构建

本包位于仓库的 `packages/snow-trip/`。`src/client/` 包含浏览器界面，`src/server/` 包含宿主服务与工具，`src/shared/` 包含共享模型；源码统一使用 `.ts` / `.tsx`，构建和测试脚本保留 `.mjs`；`test/` 包含验证脚本，`presets/` 包含插件预设，`lib/` 是未提交的构建产物。

客户端按业务组织，组件、状态和纯计算放在对应目录中：

```text
src/client/
  client.tsx       插件入口
  integration/     DSH 挂载、插槽注册和宿主操作
  workbench/       页面组合、导航布局和共享资料读取
  calendar/        首页日历与日期计算
  packages/        套餐筛选、卡片、详情、比较和删除
  plans/           方案列表、确认步骤、更新及删除
  conversation/    会话列表、操作、消息引用和对话面板
  ui/              无业务状态的按钮、筛选控件、弹窗等
```

`workbench/app.tsx` 组合页面并协调跨页面选中项；套餐探索状态由 `usePackageExplorer` 管理，会话状态由 `useWorkbenchSession` 管理，资料读取集中在 `useWorkbenchRecords`。页面切换保留筛选条件；弹窗输入与错误由弹窗组件管理。业务组件直接导入所需文件，不经过汇总导出；DSH 插槽注册集中在 `integration/`。工作台样式入口保留在 `workbench/style.css`，保持现有层叠顺序。

从仓库根目录执行 `pnpm --filter dsh-snow-trip build`、`pnpm --filter dsh-snow-trip test` 或 `pnpm --filter dsh-snow-trip typecheck`，也可进入本包目录后执行对应命令。安装依赖统一在仓库根目录执行。

`build.mjs` 在本包内执行构建：先按 `tsconfig.server.json` 用 TypeScript 直接生成 `lib/server/`、`lib/shared/` 下的运行代码和 `lib/types/` 下的声明，随后生成 Remote，按 `tsconfig.json` 严格检查整个 `src/`，最后打包客户端。所有 JavaScript 产物只写入 `lib/`，权限入口也使用编译产物。服务端不再二次打包。生成器与 esbuild 依赖由本包声明；根目录保留公共 TypeScript 配置、Remote 项目引用与 pnpm 协议识别补丁。DSH 宿主无需修改。

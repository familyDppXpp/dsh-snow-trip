# SNOW-04 · Excel 进入会话并批量确认录入

Blocked by: SNOW-03。

## 交付

从工作台选择 Excel 后进入带附件和可编辑提示词的新会话，发送后助理读取并引导批量录入，逐条展示真实保存结果。

## 范围

- 首版支持 `.xlsx`，不要求固定模板；由助理识别列名、顺序、表头位置和多表关联，不确定时向用户确认。复杂合并单元格、嵌入图片和加价矩阵不承诺全自动识别，保留来源并请求补充。

- 用 DSH 附件与输入草稿机制连接导入入口；预设提示词采用规格 §3.2 原文。
- 提供 `snow_read_material` 的 Excel 读取，复用 `readWorkbook/detect` 和现有规则提取；保留工作表与行号，支持按表和行范围读取并标记截断。
- 调整新录入路径对 `normalize()` 的依赖，不因缺金额、晚数或外部编号丢弃有意义记录，不默认补款为 0。追踪所有调用方，保留尚未移除的旧路径行为，避免拆成无用途的解析框架。
- 扩展 `snow-import` 与保存工具的批量确认、疑似重复差异和逐项结果；沿用 SNOW-03 更新校验。

## 验收

- [ ] 使用列名、列顺序及表头位置不同的合成 `.xlsx` 验证录入；不能强制用户先改成固定模板。无法确定的字段或详情归属必须追问，不猜测入库。
- [ ] 非 `.xlsx` 输入明确说明首版支持范围；复杂版式无法识别时保留资料并说明待补充项。

- [ ] 选择 Excel 后立即进入新会话，附件真实存在、提示词可改；发送前无模型请求和套餐写入。
- [ ] 修改后的提示词是实际发送内容；附件上传失败时不发送假附件。
- [ ] 合成工作簿中的主表与详情可被助理读取，结果保留具体工作表与行号。
- [ ] 缺实付金额或编号的有意义记录可作为待补全候选，而非被旧必填逻辑丢弃。
- [ ] 一次确认绑定明确的记录集合；批量部分失败时只给成功项显示成功卡片，并给出失败原因。
- [ ] 重复项经差异确认更新或新增，不覆盖未选记录。
- [ ] 大小、行列限制仍生效；不执行公式或宏；不能读取未授权附件或任意宿主路径。
- [ ] 无批量自动重试、恢复队列或自动重放；用户仍可在原会话查询结果并继续处理。

## 验证与边界

使用合成 Excel 跑附件读取→候选→确认→批量保存的入口检查，覆盖一项失败；在真实 DSH 中验证草稿发送时机。更新 SheetJS 宿主运行依赖与打包清单，不提交私人台账。解析器验证与真实模型流程验证分别记录。

依据：[规格](../spec.md) §3.2、§3.3、§4.1、§5.3。

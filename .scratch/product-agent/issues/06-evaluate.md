# SNOW-06 · 按出行意图筛选并核算套餐费用

Blocked by: SNOW-03。

## 交付

用户向助理表达日期、晚数和预算，助理追问必要信息、读取已存套餐并返回可追溯的逐晚费用和待确认项。

## 范围

- 提供 `snow-plan` 技能及 `snow_evaluate`，复用 `ledger.js` 日期、规则和逐晚计算，不交给模型心算权威金额。
- 查询、补全必要输入、计算、会话解释与来源定位形成完整路径；按实际接口共享纯计算函数，检查现有每个调用方。
- 新模型使用整数分；未知晚数、有效期、拆分条件、加价与库存不能默认有效或免费。
- 区分报价、原已付、已付补款及本次新增支出；未购买和已购买分别解释购买成本与补款。

## 验收

- [ ] 缺入住日期／必要晚数时追问，不使用虚构值计算。
- [ ] 跨日计算、离店日排除、不可用日期、重叠区间得到正确结果并保留来源。
- [ ] 未覆盖日期、规则未知时只返回已知小计和缺项，不形成完整总额或确定可用结论。
- [ ] 预算筛选保留金额未知的候选并标注未知，不将其误判为预算内。
- [ ] 未购买报价不变成已付，原已付不重复计入新增费用；0 元与未知分开。
- [ ] 同酒店不同套餐不串用规则；“规则匹配”不表达为实时有房。
- [ ] 后续读取更新版本时提示变化，旧会话计算结果不被改写。

## 验证与边界

扩展现有 `node:test` 规则回归，并运行一次“持久化查询→工具核算→会话解释”的集成检查。无实时接口、额外优化算法或新的费用引擎；本任务不做多选对比入口和保存方案。

# SNOW-10 · 已录套餐按宿主数据筛选与排序

Blocked by: 无。

## 用户确认范围（2026-09-25）

用户确认现有交互与功能均需保留。本票仅调整“已录套餐”的筛选与列表排序，以宿主中的新套餐记录为依据。本节及下方验收替代本票原有的旧流程清理、独立包验收和发布收尾要求，不补做前序任务。

本票已实施并完成下述自动检查，状态为 `ready-for-review`，等待用户验收。保留文件路径以兼容已有引用。

## 交付

“已录套餐”的筛选选项、匹配结果和列表顺序真实依据宿主套餐数据；不使用旧浏览器台账作为本列表的筛选或排序依据。

## 范围

### 数据与筛选

- 复用现有宿主套餐读取链路（`listPackages` / `host.rows`），筛选结果与卡片使用同一批新记录。
- 保留日期、住宿晚数、目的地区域及关键词筛选交互；依据新记录的目的地、有效期、禁用日期和剩余间夜排除不符合条件的套餐。关键词匹配名称、说明、酒店和雪场。
- 移除“房间补款上限（元）”筛选项及其校验、筛选逻辑和相关提示；不新增列表内补款核算或模型调用。
- 新增“套餐标签”多选筛选，复用现有状态字段：购买状态组为“已购买／未购买／待确认”，资料完整度组为“资料完整／待补全”。同组选择取并集，不同组选择取交集；未选择的组不限制结果，不新增自定义标签或标签编辑功能。
- 仅对当前启用的条件执行匹配：不符合条件，或判断该条件所需信息未知的套餐均排除；无关字段未知不影响结果。明确选择“待确认／待补全”标签时按对应状态正常匹配，不因该标签表示未知或不完整而额外排除。
- 剩余间夜按已知总间夜减已知已使用间夜判断，不将未知已使用间夜当作 0；日期检查区分未知禁用日期与已确认无禁用日期。

### 列表排序

- 取消“录入顺序”选项。
- 默认“住宿晚数从多到少”，按总间夜排序，未知排最后。
- 新增“实付金额从低到高”，仅按 `paid` 排序，不混入报价或已付额外补款；未知排最后，0 正常参与排序。
- 两种排序同值时均按记录 ID 升序稳定排列，不以创建或更新时间作为次级排序。
- 排序不额外过滤记录；某记录仅排序字段未知且不违反当前筛选条件时，保留在末尾。

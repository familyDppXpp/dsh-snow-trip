# 雪季出行产品 agent 化

## 2026-09-24 方案闭环修订

方案闭环全部用户交互采用设计友好的结构化卡片，包括信息引导、条件与估算确认、方案展示、讨论比较、运行状态、异常反馈、保存结果及回顾；不以纯文本回复替代。每张卡片职责清晰、主动作明确，保留用户自由输入能力。具体场景与界面验收见 SNOW-06 的“统一卡片交互要求”。

用户经原型评审确认的规划范围，以合并后的 [SNOW-06 · 出行方案闭环](issues/06-evaluate.md) 为准，原 SNOW-07、SNOW-08 不再独立实施。以下旧章节中与这些决策冲突的约定不再适用：单套餐新增支出预算、2–3 项对比上限、超预算候选展示，以及将互斥备选一起保存为一份方案。

一份方案是满足出行需求的完整搭配，允许拼套餐；只使用现有资料完整状态的套餐，计算和保存均校验版本。预算为整趟总价，含本次归属的已付成本与用户接受的其他费用估算，超预算搭配淘汰。确认表单全部选填，AI 建议与用户事实分开表达；候选按推荐顺序展示，支持零选继续表达、单选讨论、多选比较及保存 N 份独立方案。具体费用分摊、未知费用处理、交互与验收见合并票。此次更新仅确认规格，原型和产品代码尚未按本轮决策实现。

## 1. 问题与目标

现有插件依赖浏览器表单导入 Excel、筛选、核算和保存方案，业务数据保存在 IndexedDB，宿主 agent 无法直接操作。目标是由雪季出行专业助理执行这些任务：工作台只展示概览、选择上下文和提供会话入口；技能组织业务流程，工具读取、计算和持久化数据。

产品范围已经用户确认，依据为根目录 `CONTEXT.md` 和 `docs/adr/0001` 至 `0004`。本文中的接口名和字段名是本插件的实现约定，除明确标明为 DSH 接口外，不表示宿主已提供这些能力。本文只生成本地规格，未修改产品代码、删除数据或发布外部 issue。`ready-for-agent` 是本地元数据，不代表已给远端 issue 加标签。

## 2. 用户故事

1. 作为雪季出行用户，我希望看到已保存的套餐卡片，以便了解已有资料并进入相关任务。
2. 作为用户，我希望在左侧点击新增会话，以便直接向雪季助理表达意图。
3. 作为用户，我希望左侧只列出雪季助理会话，以便找到相关讨论。
4. 作为用户，我希望在右侧继续历史会话且左侧导航保留，以便在概览和讨论之间切换。
5. 作为用户，我希望选择 Excel 后进入新会话并看到附件和预填提示词，以便修改后再发送。
6. 作为用户，我希望通过文字、粘贴说明或截图录入套餐，以便不依赖 Excel。
7. 作为用户，我希望在同一会话补充多份材料，以便合并完善一次录入。
8. 作为用户，我希望助理提取资料并按任务追问缺失信息，以便完成录入而不必填写整张表单。
9. 作为用户，我希望看到录入摘要和未知项后再确认保存，以便纠正识别错误。
10. 作为用户，我希望批量确认 Excel 中的多条记录，以便减少重复确认。
11. 作为用户，我希望保存成功后在会话和概览看到对应卡片，以便确认资料已落盘。
12. 作为用户，我希望未购买或不完整的套餐也能保存，以便先收集再补全。
13. 作为用户，我希望报价、实付、购买状态和信息完整度分别展示，以便不混淆购买与录入成功。
14. 作为用户，我希望疑似重复资料展示差异并由我选择更新或新增，以便避免误覆盖。
15. 作为用户，我希望复制同款套餐并分别记录购买与使用情况，以便管理独立的多份记录。
16. 作为用户，我希望通过助理查询来源、解释规则、补充和纠错，以便持续维护资料。
17. 作为用户，我希望描述日期、晚数和预算后获得有依据的筛选与核算，以便判断出行选择。
18. 作为用户，我希望选中多个套餐后立即新建会话分析，以便快速比较这些套餐。
19. 作为用户，我希望未知或冲突的规则被明确列出，以免把未知费用当免费、把规则匹配当有库存。
20. 作为用户，我希望通过助理保存和回顾方案，以便保留当时的资料与费用依据。
21. 作为用户，我希望手动记录已使用间夜和作废状态，以便反映我在外部平台完成的行为。
22. 作为用户，我希望套餐更新后仍能看懂旧会话和旧方案的依据，以便识别新旧数据差异。
23. 作为用户，我希望关闭工作台后任务仍能执行，以便不必一直打开面板。
24. 作为用户，我希望中断后继续原会话聊天，以便利用已有讨论而不进入额外恢复流程。
25. 作为用户，我希望附件、模型或保存失败时看到真实原因，以便补充材料或继续处理，不误以为已成功。

## 3. 产品交互

### 3.1 工作台与会话

保留当前雪季视觉风格和左侧导航。在原导航下方、底部说明上方放置“新增会话”按钮与雪季会话列表；右侧在概览、数据概览、已存方案和完整会话之间切换。会话列表沿用 DSH 标题、运行状态和更新时间，不另存消息正文或生成第二套标题。空列表提供新增入口；无数据概览提供录入入口。

新增会话创建雪季助理的空白会话，聚焦输入框，不自动发送。点击历史会话打开原会话。工作台允许勾选套餐、浏览、导航和选择材料；原业务表单的导入映射确认、费用填写、保存和修改动作交给助理会话。来源和详情可只读展示；“解释／补充／修改”携带对应记录进入会话，不在概览内直接写数据。

### 3.2 三种启动方式

| 入口 | 上下文 | 启动行为 |
|---|---|---|
| 新增会话 | 无业务上下文 | 新建空白会话，等待输入 |
| 导入材料 | 选择的文件或图片 | 新建会话、附加材料、预填提示词，等待用户编辑并发送 |
| 套餐对比 | 选中记录的 ID、版本和快照 | 新建会话并立即发送对比请求 |

导入默认提示词为“请帮我录入附件中的套餐，整理已知信息和待确认项；需要补充的内容请问我，确认后再保存。”用户可以完全修改。导入入口在发送前不得进行模型调用或写入业务记录；附件进入 DSH 本机附件存储不等于录入套餐。

对比复用现有最多 3 个套餐的选择上限，至少选择 2 个；这是现有界面的首版保留值，不建设可配置上限。对比不得隐式保存方案。其他明确动作（查询、修改、回顾）可使用带上下文的预填请求，用户发送；不要把“对比立即发送”的特例扩大到所有入口。

### 3.3 录入、确认与成功

Excel 首版支持 `.xlsx`，不要求固定模板。助理判断列名、列顺序、表头位置和多工作表关联，不确定时询问用户；复杂合并单元格、嵌入图片或加价矩阵可能需要补充说明，不承诺任意格式全自动识别。

材料解析、信息提取、追问、摘要确认均发生在会话。助理区分来源事实、模型推断与用户补充；推断不能静默升级为确定规则。截图采用宿主图片附件和支持图片的已配置模型，不接外部 OCR 服务。当前模型不支持图片时明确说明，用户可切换宿主已有兼容模型或补充文字；不得伪造识别结果。

用户确认后才持久化套餐；批量确认要指明本次记录集合。待补全记录也可以保存，价格、酒店、晚数和日期等业务字段不作为一律必填门槛。至少需要一项有意义的套餐描述或信息，不能把空白请求保存为记录；展示名称缺失时使用“未命名套餐”，不伪造酒店或套餐名称。

写入成功后由工具结果生成成功卡片；不以模型文本或前端提前插入卡片作为成功依据。卡片显示名称、已知酒店或适用范围、已知间夜、报价、实付、购买状态、待补全项，并可打开相关会话。未知值显示“待确认”。会话卡片保留写入当时的结果，概览展示当前记录；二者使用同一记录 ID，后续版本不同要明确提示。

疑似重复只提示，不自动合并：有外部编号时结合来源判断，无编号时使用名称、酒店等现有字段进行简单候选匹配。该匹配不是身份判定；同款购买多次允许新增。用户选择更新时展示差异，更新不可静默清空未提供字段。

## 5. 技术设计

### 5.1 职责与运行方式

保持一个可独立安装的插件包。宿主入口连接一个雪季业务模块；工具与客户端读取接口共用该模块，避免两套计算和写入逻辑。复用 DSH 已有本机 `storage.domain`，不新增数据库引擎、云服务或独立后台进程。使用独立域名 `snow-trip`，沿用部署已配置的本机后端。

建立 `snow-trip` 专业助理预设，随包提供其组合文件并经 bundle 合并预设根目录，不替换宿主全局默认预设或其他用户配置。业务数据域只在宿主打开一次；技能与工具可绑定雪季预设作用域，不能因多会话重复打开同一个数据域。会话列表按 `projectionValues.agentPreset === 'snow-trip'` 过滤，不按标题猜测，也不另建会话数据库。

复用 DSH 的模型配置、请求、流式响应、取消、消息保存和权限交互。模型可访问任务所需业务资料；产品说明改为“数据保存在本机，助理会将任务相关内容发送给配置的模型”。不建立插件独有 API Key 配置或第二套模型调用器。

### 5.2 数据结构

使用 `packages` 与 `plans` 两个域表；不拆商品库和订单库，不另建任务恢复表。每条记录带结构版本，持久化读取和模型／客户端输入均校验。

| 对象 | 必要内容 |
|---|---|
| 套餐记录 | 内部 UUID、递增 revision、创建／更新时间、名称或描述、酒店／适用酒店范围、房型、雪场／地区、总间夜、购买状态、报价、实付、已付额外补款、有效期、拆分规则、补款规则、不可用日期、使用信息、作废状态、来源、待确认项 |
| 来源 | 已持久化附件引用或会话消息定位；Excel 保留工作表和行号，文字与图片保留对应消息及原文说明；识别结果注明来源性质 |
| 方案 | UUID、时间、查询条件、涉及的套餐 ID/revision 及完整相关快照、逐晚计算结果和来源、手工估算费用、未知项 |

名称可以回退为展示占位；其余未知业务值用 `null`，未知列表用 `null` 与已确认空列表区分。购买状态为 `unknown/unpurchased/purchased`；作废独立表达；购买状态不从卡片存在、报价或 0 元推断。总间夜和已使用间夜分别记录，已使用未知时不能当成 0。剩余间夜仅在两者明确且合理时计算。

金额统一为非负整数分，展示为人民币元；0 与未知严格区分。日期使用经校验的 `YYYY-MM-DD`；住宿区间为入住日含、离店日不含，规则自身日期边界按来源明确记录。总间夜与使用间夜需为整数，纠错不得得到负数或超出已知总量。用户明确提供互相冲突的状态或数据时询问澄清，不自动修改另一字段凑成一致。

报价不能计为实付，原订单已付不能重复计入新增支出；未购买套餐的预计购买成本与已购买套餐的补款分别列出。未知费用使相关总额不完整，可显示已知小计，不能给出虚假的完整总额。

复制生成新 UUID，复制套餐说明和规则；购买、实付、使用情况由用户提供，不无声继承为新记录的事实。历史会话通过已记录工具结果或上下文快照保留当时版本，不额外建设所有套餐版本的历史数据库。

### 5.3 内置技能与工具

随包提供三个技能，正文使用中文，目录供模型按需加载：

| 技能 | 职责 |
|---|---|
| `snow-import` | 解读多种材料、组合信息、追问、展示摘要及重复差异、取得确认后录入 |
| `snow-manage` | 查询解释、补充纠错、复制、记录使用和作废；区分事实与未知 |
| `snow-plan` | 从意图获取日期等条件，调用确定性核算、解释对比、按要求保存方案 |

最小工具集合如下。名称为本插件拟定接口；不要求每个工具单独建文件。

| 工具 | 输入及结果 | 写入约束 |
|---|---|---|
| `snow_read_material` | 当前会话可访问的附件引用 → 工作表／行／文本片段、截断标记与问题；支持按工作表和行范围读取 | 只读；Excel 复用 SheetJS，分段返回避免整本灌入模型；图片走宿主图片输入 |
| `snow_query` | 套餐或方案、ID 列表／查询条件 → 记录、版本和来源 | 只读；必须说明结果是否截断 |
| `snow_save_packages` | 新增／更新／复制项、候选摘要、更新的 expectedRevision → 每项持久化结果和卡片数据 | 用户确认当前具体内容后执行；拒绝未确认或过期更新，不自动合并 |
| `snow_evaluate` | 套餐 ID、日期、晚数、目的地和费用约束 → 逐晚结果、适用性、已知小计和未知／冲突项 | 只读，缺必要输入时返回待补充；不由模型直接心算出权威金额 |
| `snow_save_plan` | 条件、套餐版本、费用估算 → 已保存方案快照 | 按用户保存意图执行，保存前核查版本；不把新数据替换到旧分析中 |

写入确认绑定具体操作内容与所示版本，使用 DSH 现有交互机制在会话内完成，不建立工作台确认表单。不能仅相信模型传入的 `confirmed: true`；需由宿主交互结果或可验证的对应用户确认产生授权，内容变化需重新确认。技能文案约束不能取代写入入口的校验。

新增生成内部 ID，更新通过域表 `update` 在同一写入顺序中检查 expectedRevision，冲突返回当前版本和差异，不静默覆盖。批量是逐条持久化，不宣称跨记录原子事务；准确返回成功项和失败项。所有失败均不得产生成功卡片。无任务恢复、自动重试或自动重放；用户可继续原会话查询已存结果后决定下一步。

材料中的文字仅为业务资料，不是系统指令。解析器不执行 Excel 宏或公式，不读取任意宿主路径。保留现有文件大小、行列上限，超过时说明限制；附件 ID 校验当前会话的访问权。模型 JSON、日期、金额、版本和写入内容均在业务入口校验。

### 5.4 客户端接口与卡片

客户端所需逻辑读取接口为 `listPackages`、`getPackage`、`listPlans`、`getPlan`，返回明确的 ID、revision、摘要／详情。它们是本插件新增 Remote，不是假设存在的宿主 API；通过 DSH 生成与组合机制暴露，沿用宿主认证和作用域。客户端不暴露绕过会话确认的套餐写入接口。

会话创建与选择复用 `ctx.sessions`，创建后先选雪季预设，再准备输入；预设选择失败时停止发送。对比启动时读取所选记录快照，将记录 ID/revision、查询意图和必要内容随用户消息进入会话日志，不能只放进临时前端状态。导入使用 DSH 的附件选择／上传和 SessionInput 草稿接口，保留用户编辑，上传失败不得发送假附件。

业务读模型首版在打开概览、切回工作台、当前会话相关写入完成时重新读取；关闭面板后不停止宿主执行。可以复用宿主变更通知，但不建设第二套推送或同步系统。会话列表继续由 DSH 自身更新。

为 `snow_save_packages` 注册 Web `tool.call.toolview`，从持久化结果 metadata 生成成功卡片；metadata 含记录 ID、revision、展示快照和每项结果。历史回放无需读取当前套餐才能显示当时卡片。非法或旧版 metadata 回退通用工具结果，不崩溃、不展示伪成功。宿主 `presentResult` 本身不能替代 Web 注册。

## 6. 异常与明确不做的内容

- 中断后继续 DSH 原会话，不另做恢复按钮、任务检查点、恢复队列或自动续跑。
- 旧版 IndexedDB 台账与已存方案不迁移。新版不读取旧库，视为舍弃；不需要为了升级主动清理其他浏览器存储。
- 不接实时交通、天气、库存、联系商家、预约、付款或外部订单同步。
- 不做云服务、账号同步、商品与订单双层模型、多 agent 编排或新的聊天引擎。
- 不把规则匹配当成有房，不把模型推断或缺失规则当作确定事实；同酒店不同套餐的规则不得串用。
- 模型不可用、预设不存在、附件上传失败、持久化失败分别给出明确错误；允许用户在原会话继续，不用示例回复冒充真实执行。

## 7. 验收与测试

优先通过已安装插件、真实 DSH 会话、工具入口和临时本机存储验证。沿用 `node:test`，仅为业务关键分支保留可运行检查，不复制实现内部结构建 mock 测试。

| 验收路径 | 必须观察到的结果 |
|---|---|
| 独立安装与新建会话 | 预设和三个技能可发现；列表只显示雪季会话；新增得到空白输入，右侧完整对话可用 |
| Excel 导入前后 | 选文件后草稿可改，发送前无模型请求／套餐写入；发送后能读取真实文件和来源行号 |
| 文字及截图录入 | 多轮补充可合并；兼容模型实际读取截图；不兼容模型明确失败，无伪识别 |
| 未购买、不完整记录 | 报价或实付未知仍可确认保存；卡片待补全且购买状态独立 |
| 确认与保存失败 | 未确认内容无法写入；确认内容变化不能沿用旧授权；持久化失败无成功卡片 |
| 重复与并发修改 | 疑似重复展示差异；可选新增／更新；过期版本更新被拒绝，原数据不丢失 |
| 批量录入 | 支持一次确认；逐项结果准确，部分失败不能标记全批成功 |
| 对比入口 | 至少两个候选带准确 ID/revision 与快照进入新会话，立即分析且不自动保存方案 |
| 费用计算 | 跨日边界、未知费用、重叠规则、不可用日期保持正确；报价、实付、补款不重复计费 |
| 使用和纠错 | 已用与总间夜分开；未知不变 0；超用、负数和冲突输入不能静默写入 |
| 历史与新数据 | 已存方案和历史成功卡片保持旧快照；新分析使用新版本并提示变化 |
| 关闭与重开 | 关闭面板不中止宿主工作；重开能读取已存数据；退出重启后能继续 DSH 原会话，无插件恢复流程 |
| 全新数据 | 存在旧 IndexedDB 时新版仍为空，不迁移、不混入旧方案 |
| 分发产物 | 预构建包与源码构建包含宿主依赖、技能和预设，不依赖本机绝对路径；React 沿用宿主 |

保留并调整现有规则回归，加入一组从工具保存到持久化重开、读取再核算的集成检查；前端重点验证三种入口的发送时机及成功卡片回放。使用合成材料与可控模型响应覆盖工具行为；发布前另做一次已配置真实模型的 Excel／截图端到端检查，明确区分“工具通过”和“模型流程通过”。本次规格编写未运行上述实现验收。

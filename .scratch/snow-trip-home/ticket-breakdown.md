# 首页任务拆分记录

用户已确认任务粒度、顺序与依赖，5 张任务已发布至本地 [任务索引](issues/README.md)。父规格保持不变，产品代码未修改；仅 HOME-01 设置 `ready-for-agent`，其他任务标记为等待前置任务。

## 拆分依据

当前 `App` 已有页面状态、宿主数据读取和详情入口，`SnowTrip` 已有认证 Remote 与持久化。没有证据表明必须先做独立重构，因此不设预重构任务，不做全局状态管理或模块重组。

采用五个用户行为切片；每票包含其必要的数据、逻辑、接口、界面与验证，不按数据库/后端/前端横向分票。无需新存储的任务直接复用现有数据。地图工作拆为可浏览地点、安全底图、自动定位、人工确认和月份筛选，避免把全部外部服务接入塞进一票。

| 编号 | 标题 | 阻塞依赖 | 可独立验收的交付 |
| --- | --- | --- | --- |
| HOME-01 | 从首页月历查看套餐与行程 | 无 | 默认首页、按日计数、日期明细、导航与草稿保持 |
| HOME-02 | 切换地图并浏览酒店与雪场清单 | HOME-01 | 独立地图视图、真实底图、地点列表与服务失败降级 |
| HOME-03 | 自动定位明确地点并保存结果 | HOME-02 | 宿主查询与持久化、自动点位、快照关联和去重 |
| HOME-04 | 确认歧义地点并纠正位置 | HOME-03 | 候选选择、改词重查、更正位置和并发保护 |
| HOME-05 | 按月份查看地图分布 | HOME-03 | 独立月份筛选、分段地点匹配、未知日期分组 |

依赖图：`HOME-01 → HOME-02 → HOME-03 → {HOME-04, HOME-05}`。默认顺序 01、02、03、04、05；04 与 05 没有互相阻塞关系。此图不意味着授权启动多个 agent。

外部条件独立于任务依赖：HOME-02 的真实底图验证需要 JS Key 与安全代理配置；HOME-03/04 的真实查询验证需要有效 Web 服务 Key。自动测试可以使用外部边界替身；未具备配置时仍可完成本地开发，但相应真实服务验收必须保持未完成，不能以降级页面替代。

## HOME-01：从首页月历查看套餐与行程

已发布路径：`issues/01-home-calendar.md`

Blocked by: 无

用户结果：打开应用先看到月历，选择日期即可知道哪些套餐日期规则允许入住、哪些方案在行程中，并打开明细。

范围：复用 `actions.listPackages/listPlans` 与现有日期库，在 `App` 增加首页和品牌返回；实现按日聚合、年月导航、待确认列表、已有详情入口；保留会话草稿与执行状态。以小的首页组件/纯计算函数承载新增内容，按实际需要提取，不借机重构整个工作台。本票只交付月历，地图切换随 HOME-02 加入，不展示不可用的假按钮。

验收标准：

- [ ] 首次打开和有上次会话时均默认首页；桌面/移动端品牌可用键盘返回首页；原套餐、方案、会话入口继续可用。
- [ ] 本地当月、周一开头；支持前后月、年月选择、本月；初始无选中日，切月清除选择；日期明细位于下方，方案先于套餐。
- [ ] 套餐按单晚计数，包含有效期首尾，排除禁用日、明确作废与已知耗尽；不要求从选定日期能住满套餐；购买状态不改变日期计数。
- [ ] `unavailableDates: null` 与空数组区别处理，缺日期分组标为待确认；缺全部日期不铺满每格；未知使用量和限制在明细提示，不自动推断。
- [ ] 方案包含离店日；总日期缺失时按分段并集显示，不填补空档；跨月、跨年、闰日正确，套餐/方案分别按 ID 去重。
- [ ] 加载、失败、空库与当日无结果各有独立状态；一类数据读取失败不伪装为 0，也不阻止另一类阅读；空库可开始录入。
- [ ] 从日期明细进入现有详情/会话，返回保留本次浏览状态；未发送草稿和执行中会话不受影响；保存、修改、删除后重新聚合，迟到请求不恢复旧记录。
- [ ] 真实 App 浏览器测试覆盖导航、日格与明细、窄屏及键盘；日期行为测试覆盖规格中的 A/B/C 跨年样例和未知值；既有筛选测试改为显式进入原页面，保留原断言。

必要层次：已有宿主读取 → 日期逻辑 → 月历/详情 UI → 行为与浏览器测试。无新 schema 或 Remote。

范围外：地图、定位、补款计算、对原筛选语义的更改。

## HOME-02：切换地图并浏览酒店与雪场清单

已发布路径：`issues/02-map-browse.md`

Blocked by: HOME-01

用户结果：在首页切到地图，看到酒店/雪场的地点清单及其关联记录；配置有效时显示真实底图，未定位条目明确列出。

范围：从当前套餐和历史方案快照提取地点，展示两个角色及记录关联；新增 `getMapConfig`、插件配置和高德安全代理接入，客户端加载底图。先验证宿主路由/配置能力，不假设现有代理已经存在；必要时仅添加地图专用受限代理，不提供通用转发服务。

验收标准：

- [ ] 首页提供月历/地图切换，首次默认月历，重新打开记住视图；偏好存储失败可继续操作；月历状态在本次切换中保留。
- [ ] 地点来自当前套餐的 hotels/resort 与方案快照，快照不作为新增套餐计数；多个适用酒店保留“适用酒店”含义，不显示为实际已订酒店。
- [ ] 酒店和雪场有文字与不同图标；缺名称、无法定位单独列出；点位尚未解析时不放置虚构坐标；清单可查看关联记录并键盘操作。
- [ ] 宿主返回的公开地图配置不含 Web 服务 Key 或安全密钥；安全代理固定合法上游，拒绝任意目标转发；凭据不进入源码、包产物或日志。
- [ ] 有效配置加载真实底图；无配置、授权失败、脚本失败时保留地点清单与月历，并提供明确状态和重试。
- [ ] 地图脚本按需单次加载，离开时销毁实例与事件；重试和重复切换不重复注册、不抢焦点、不影响草稿。
- [ ] 浏览器检查覆盖真实 App 的切换、记忆、列表与降级；配置接口/代理检查覆盖秘密隔离和上游限制；配置后的真实底图加载结果单独记录。

必要层次：宿主配置/受限代理与 Remote → 客户端 actions → 地点关联与地图/列表 UI → 接口和浏览器验证。

范围外：自动查询、地点持久化、候选选择、月份筛选。此票是可浏览的基础切片，不代表完整地图功能完成。

## HOME-03：自动定位明确地点并保存结果

已发布路径：`issues/03-auto-locate.md`

Blocked by: HOME-02

用户结果：进入地图后明确的酒店/雪场自动标点，重新打开能复用位置，点位展示关联套餐和方案。

范围：新增宿主 `places` 表、`resolvePlaces` 与高德 POI 查询，接入实际 App 点位与缓存状态。查询身份用供应商/类型/名称/地区，点位用供应商 POI ID 聚合；持久化追加不改变 packageRecord、planRecord 或历史快照。

验收标准：

- [ ] 通过存储库支持的机制追加 places；旧四张表数据升级前后可读，重启后定位记录保留，不清库；实现前验证追加表/版本契约。
- [ ] `resolvePlaces` 每批至多 50 个合法记录引用，由宿主读取实际名称与地区；非法 ID、快照关联、类型或酒店下标被拒绝，网络不接收客户端任意上游 URL。
- [ ] 优先读取持久化结果；仅查询缺失项，同身份进行中请求合并，并发不超过 2、超时 10 秒；批次逐项返回，单项失败不抹去其他结果。
- [ ] 只有唯一名称精确匹配、类型相符且地区可验证相符的候选自动定位；单个模糊结果、多个结果或缺依据均列为待确认，不选排名第一。
- [ ] 坐标有限且范围有效，明确坐标系；外发内容仅名称、地区、类型；错误不覆盖已有成功记录，离线缓存仍能读取，失败有手动重试。
- [ ] 点位区分酒店与雪场；相同 POI 两种角色均可见，接近坐标不强行合并；各点关联数与全图总数分别按套餐/方案 ID 去重。
- [ ] 当前套餐地点修改后查询新身份；已存方案继续关联旧快照；删除/更新后旧异步结果不能复活原关联；首次适配点位，普通刷新不重置缩放。
- [ ] 测试经宿主公开接口验证唯一/模糊/无结果/失败与缓存重启；App 验证两个点关联同一套餐但总数为 1；记录真实酒店、雪场查询并显示点位的冒烟结果。

必要层次：places schema/存储兼容 → 查询与 Remote → actions → 点位/待定位 UI → 宿主集成与浏览器测试。

范围外：本票只展示歧义状态，候选选择与纠正在 HOME-04 完成；不做多供应商或后台定时查询。

## HOME-04：确认歧义地点并纠正位置

已发布路径：`issues/04-confirm-place.md`

Blocked by: HOME-03

用户结果：用户可在候选中选对位置，查无结果时改词重试，并更正已定位地点；选择重启后保留。

范围：在 HOME-03 的地点记录上增加人工来源/版本校验能力，新增 `searchPlace`、`confirmPlace`、宿主短期候选查询标识及完整操作界面。保存位置只更新展示元数据，不改套餐文本或方案快照。

验收标准：

- [ ] 待定位列表按歧义、缺名称、无结果说明原因；候选显示名称、地址、类型，可键盘选择，窄屏完整可用。
- [ ] 用户修改检索词/地区后可重新查询，但不改变原始套餐字段；上游无覆盖时保留待定位，不猜国内同名点。
- [ ] 确认请求只传查询 ID、候选 ID、期望版本；宿主从自己保存的查询结果取坐标，拒绝失效或不属于该查询的候选，拒绝版本冲突。
- [ ] 成功保存后列表和地图使用相同位置，重启后仍保留；修改一处共享地点解析时所有关联一致更新。
- [ ] “更正位置”可重新查询选择；保存失败保留候选/选择及上次成功位置，不显示已保存；取消不改记录。
- [ ] 自动查询迟到不能覆盖用户手选；并发更正不静默覆盖；引用已修改或删除时不能将旧查询结果错误应用到新地点。
- [ ] 通过宿主接口与真实 App 验证候选确认、更正、错误/重试、重启和并发；外部响应按文本显示；完成一次真实候选选择并刷新确认保留。

必要层次：候选生命周期/存储版本 → 查询与确认 Remote → 客户端表单与地图更新 → 集成及浏览器验证。

范围外：手写经纬度输入、套餐编辑器、模型工具、自动改写地址。

## HOME-05：按月份查看地图分布

已发布路径：`issues/05-map-months.md`

Blocked by: HOME-03

用户结果：地图默认看全部地点，选择月份后只查看当月相关的套餐与方案，日期不确定的记录仍可找到。

范围：复用 HOME-01 的日期口径与 HOME-03 的地点关联/缓存，实现月份筛选、分段方案地点判定及地图/列表一致性。无需新增 Remote 或 schema，不能为筛选重复请求已有地点。

验收标准：

- [ ] 新打开地图默认“全部月份”，包括历史、作废、耗尽记录并显示状态；提供指定月份与恢复全部操作。
- [ ] 月份与月历独立，本次切换视图保留各自状态，重新打开只恢复视图种类；选择月份不重复查询已解析地点。
- [ ] 套餐至少一天确定可用才进入当月确定结果；日期不足单独分组，明确不可用不进入该月；全无日期不伪装当月有效。
- [ ] 方案按行程与月份相交计数；多段只关联当月相交分段的地点，缺快照关联标为待确认，不混入其他月份酒店。
- [ ] 当月套餐/方案总量按 ID 去重，双角色与多地点不增加总数；日期待确认但已定位的记录单独展开，不混入确定点位。
- [ ] 筛选后失效地点选择被清除并重新适配范围；无结果、部分数据错误和全部未定位时保留可理解的列表/空态。
- [ ] 资料更新、删除和迟到响应之后地图、地点清单、数量同步，不恢复旧结果；返回详情后的筛选保持。
- [ ] 浏览器和聚合测试覆盖跨年、双角色、分段跨月、未知日期、清除筛选和键盘操作；与 HOME-04 的合并验证在二者均完成后执行，不构成开发互相阻塞。

必要层次：现有宿主记录 → 日期/分段与地点集合 → 月份控件/地图/列表 → 行为及浏览器测试。

范围外：双视图联动、路线、库存查询、自动选择实际酒店。

## 通用执行与交付约束

- 所有票保留工作区既有修改；不额外发布远端任务、提交或部署。
- 每票至少留下其验收要求对应的可重复检查，复用真实 App 和认证宿主边界；只替代外部供应商响应，不逐个 mock 内部实现。
- 每票完成后运行受影响的测试；涉及构建/类型时运行相应检查。五票合并后执行 `pnpm typecheck`、`pnpm test`、`pnpm build` 和首页浏览器回归，记录真实地图冒烟结果。
- 合并验证不是第六张“补测试”票。最后合入任务的执行者负责整体检查；各票自己的测试不可推迟。
- 没有凭据时说明真实服务验收尚缺，不能勾选对应项。配置条件不会阻止 HOME-01 的月历开发。
- 正式发布后，HOME-01 初始标记 `ready-for-agent`，HOME-02 至 HOME-05 标记 blocked；依赖完成后再更新就绪状态，不预先宣称全部可执行。
- 任务各自以本文件验收清单加父规格为边界，避免把整套地图完善、全站重构或额外体验需求塞进单票。
